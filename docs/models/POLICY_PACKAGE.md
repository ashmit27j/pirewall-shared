# Policy Package Specification

Version: 1.0

Status: Draft

---

# Purpose

A Policy Package represents a signed, advisory security package generated by the Pirewall Cloud.

It contains a single recommended policy action derived from historical analysis, threat intelligence, administrator-defined policies, and offline model evaluation.

A Policy Package is advisory only.

It cannot directly modify the firewall or execute system commands.

The Raspberry Pi remains the sole Policy Enforcement Point (PEP).

---

# Philosophy

The cloud advises.

The Raspberry Pi decides.

Policy Packages communicate security intent, not implementation details.

Every package must be independently verified before use.

# Required Fields

## Metadata

- Package ID
- Package Version
- Creation Timestamp
- Expiration Timestamp
- Policy Engine Version

---

## Recommendation

- Recommended Action
- Target Type
- Target Value
- Duration (if applicable)
- Priority

---

## Reasoning

A human-readable explanation describing why the recommendation was generated.

Examples:

- Repeated SSH brute-force behaviour
- High-confidence malicious flow
- Threat intelligence match
- Administrator policy

---

## Constraints

Optional execution constraints.

Examples:

- Maximum duration
- Scope limitation
- Required validation level
- Allow administrator override

---

## References

- Threat Assessment ID
- Related Flow IDs (optional)
- Threat Intelligence Reference (optional)

---

## Integrity

Every Policy Package shall include:

- Digital Signature
- Signature Algorithm
- Package Hash

Unsigned Policy Packages shall never be accepted.

---

# Validation Rules

A valid Policy Package shall satisfy:

- Valid Package Version
- Valid Recommendation
- Existing Threat Assessment reference
- Valid Signature
- Non-expired timestamp
- Non-empty reasoning

---

# Explicitly Forbidden

Policy Packages shall never contain:

- nftables commands
- Shell commands
- Python code
- Executable scripts
- Raw firewall syntax
- Machine learning models
- Direct enforcement instructions

# Versioning

Every Policy Package records:

- Package Schema Version
- Policy Engine Version
- Threat Assessment Version

Breaking schema changes require a new major version.

---

# Performance Requirements

Policy Packages should remain compact.

They are exchanged only through background synchronization and must never delay packet processing.

---

# Security

Policy Packages are advisory.

The Raspberry Pi shall:

- Verify the digital signature.
- Verify package integrity.
- Verify expiration.
- Validate package contents.
- Reject invalid packages.

Only validated packages may be passed to the Rule Compiler.
